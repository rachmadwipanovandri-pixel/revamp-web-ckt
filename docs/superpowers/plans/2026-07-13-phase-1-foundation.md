# Phase 1 — Foundation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Scaffold the Next.js project with design tokens, self-hosted fonts, a testing harness, next-intl bilingual routing (EN default at root, ID at `/id`), and a working Navbar + Footer shell that renders in both locales.

**Architecture:** Next.js App Router with all routes nested under `src/app/[locale]/`. `next-intl` provides `localePrefix: "as-needed"` routing plus a request-scoped message dictionary. Design tokens from `docs/01–03` are expressed as CSS variables in `globals.css` via Tailwind v4's `@theme`, consumed by shadcn/ui primitives. Pure helpers (SEO alternates, locale utilities) live in `src/lib/` and are unit-tested with Vitest.

**Tech Stack:** Next.js 16 (App Router, TypeScript, Turbopack), Tailwind CSS v4, shadcn/ui, next-intl v4 (4.13+, declares `next: ^16` support), `@iconify/react`, `next/font`, Vitest + React Testing Library.

---

## Runtime Note — Next.js 16

`create-next-app@latest` resolved to **Next.js 16.2.10** (a fresh major). Two breaking changes are relevant to this plan:

1. **`middleware.ts` → `proxy.ts`.** Next 16 renamed the Middleware convention to Proxy (a `proxy.ts` file at the same level as `app`, exporting a `proxy` function or a default export). Functionality is identical. This plan uses `src/proxy.ts` for next-intl's routing handler (Task 6). `middleware.ts` still works but is deprecated — do not use it.
2. **Async `params`/`searchParams`.** Route `params` are Promises (already reflected in every layout/page in this plan via `params: Promise<...>` + `await`).

The scaffold also generated `AGENTS.md`/`CLAUDE.md` at the repo root pointing agents to `node_modules/next/dist/docs/`. Implementers: when a Next.js API behaves unexpectedly, consult that bundled doc set and heed deprecation warnings rather than assuming pre-16 behavior.

## Runtime Note — shadcn/ui on Base UI (not Radix)

`shadcn@latest` (4.13) now scaffolds the **"base-nova"** style built on **`@base-ui/react`**, not Radix. Consequences for this plan and later phases:

1. **No `asChild`.** Base UI's `Button` has no `asChild`/Slot. To render a link that looks like a button, use `buttonVariants()` on the element directly: `<Link href="/contact" className={cn(buttonVariants({ size: "sm" }))}>…</Link>` (Task 11 uses this). For other primitives, Base UI uses a `render` prop instead of `asChild`.
2. **Transitions use Base UI data attributes** (`data-starting-style` / `data-ending-style`), not `tw-animate-css`. Our authoritative `globals.css` (Task 9) drops shadcn's generated `@import`s, so those transition variants are currently unregistered — components still open/close, just without animation. This is cosmetic; revisit when a `Sheet`/dialog is actually mounted (Task 11) or during Phase 2 polish.
3. `lucide-react` is installed as a shadcn dependency, but per the PRD our own icons use `@iconify/react`.

## Plan Scope

This is **Plan 1 of 6**, mapping to PRD §16 Phase 1. It delivers the running bilingual shell that every later phase builds on. Out of scope here (each gets its own plan): homepage sections (Plan 2), product pages (Plan 3), contact form + UTM/leads pipeline + legal pages (Plan 4), blog/WordPress (Plan 5), SEO/analytics/launch (Plan 6).

**Definition of done for this plan (PRD §16 Phase 1 exit criteria):**
- `npm run build` succeeds.
- `/` renders in English, `/id` renders in Indonesian, each with exactly one `<h1>` and correct `<html lang>`.
- Design tokens (colors, fonts, radius, shadow) are applied and resolvable.
- Navbar (with working language switcher + mobile drawer) and Footer render on both locales.

const SITE_URL = process.env.NEXT_PUBLIC_SITE_URL ?? "https://cekat.ai";
const DEFAULT_LOCALE = "en";

export function htmlLang(locale: string): string {
  return locale === "id" ? "id-ID" : "en";
}

export function localizedPath(locale: string, pathname: string): string {
  const clean = pathname === "/" ? "" : pathname;
  if (locale === DEFAULT_LOCALE) return clean || "/";
  return `/${locale}${clean}`;
}

export function alternates(pathname: string) {
  return {
    canonical: `${SITE_URL}${pathname}`,
    languages: {
      en: `${SITE_URL}${localizedPath("en", pathname)}`,
      "id-ID": `${SITE_URL}${localizedPath("id", pathname)}`,
      "x-default": `${SITE_URL}${localizedPath("en", pathname)}`,
    },
  };
}
```

import type { ReactNode } from "react";
import { notFound } from "next/navigation";
import { NextIntlClientProvider, hasLocale } from "next-intl";
import { setRequestLocale } from "next-intl/server";
import { routing } from "@/i18n/routing";
import { htmlLang } from "@/lib/seo";
import { fontSans, fontNumeric } from "@/lib/fonts";
import "../globals.css";

export function generateStaticParams() {
  return routing.locales.map((locale) => ({ locale }));
}

export default async function LocaleLayout({
  children,
  params,
}: {
  children: ReactNode;
  params: Promise<{ locale: string }>;
}) {
  const { locale } = await params;
  if (!hasLocale(routing.locales, locale)) notFound();
  setRequestLocale(locale);

  return (
    <html
      lang={htmlLang(locale)}
      className={`${fontSans.variable} ${fontNumeric.variable}`}
    >
      <body className="min-h-screen bg-background text-foreground">
        <NextIntlClientProvider>
          <main>{children}</main>
        </NextIntlClientProvider>
      </body>
    </html>
  );
}
```

```tsx
"use client";

import { Link, usePathname } from "@/i18n/navigation";
import { routing } from "@/i18n/routing";
import { cn } from "@/lib/utils";

const LABELS: Record<string, string> = { en: "EN", id: "ID" };

export function LanguageSwitcher({ currentLocale }: { currentLocale: string }) {
  const pathname = usePathname();
  return (
    <div className="flex items-center gap-1 text-xs font-semibold">
      {routing.locales.map((locale) => {
        const active = locale === currentLocale;
        return (
          <Link
            key={locale}
            href={pathname}
            locale={locale}
            aria-current={active ? "true" : undefined}
            className={cn(
              "rounded-sm px-2 py-1 transition-colors",
              active ? "bg-surface-subtle text-foreground" : "text-muted-foreground hover:text-foreground",
            )}
          >
            {LABELS[locale] ?? locale.toUpperCase()}
          </Link>
        );
      })}
    </div>
  );
}
```
